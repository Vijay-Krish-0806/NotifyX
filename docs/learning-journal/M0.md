## Why

- **Self-contained CLAUDE.md:** the "Done when" requires a session given only the repo to know the rules, so rules kept outside the repo do not count.
- **Permission rules, not hooks, for hard limits:** the official docs recommend permission rules for allow and deny; hooks are for automation.
- **Just-in-time tooling:** rules, subagents and hooks are created when real code exists for them to act on, not up front.
- **Docs created on first real content:** empty stubs drift; the docs index lists each planned doc and its expected milestone.
- **LF line endings in the repo:** CRLF breaks shell scripts inside Linux containers.

## What failed or surprised

- The first `git restore --staged` failed because a repo with no commits has no HEAD; `git rm --cached` was the right command.
- The first push failed with a stale GitHub credential (password authentication is not supported); fixed by signing in again through the credential manager.
- Windows PowerShell 5.1 cut a prompt short at embedded double quotes when passing it as an argument; sending it through stdin worked.
- A committed `permissions.allow` list is ignored in an untrusted folder ("Ignoring 18 permissions.allow entries… workspace has not been trusted"), while `ask` and `deny` still apply. This matches the docs: a cloned repo cannot grant itself permissions.
- Permission rules match command text, so they are a guard rail, not a security boundary (for example, `git -C . push` is not matched by `Bash(git push *)`).
