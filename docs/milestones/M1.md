# M1: Foundation + infra (checklist)

Approved kickoff plan for M1, so each step can be run in a fresh session. Source of truth: [NOTIFYX_BUILD_PLAN.md](../../NOTIFYX_BUILD_PLAN.md) §8 M1.

**How to use:** run one step per session. Read this file, the plan's M1 section and the docs the step touches. Verify the library APIs the step uses against the official docs and state the versions. Build, run the check, show real output, commit with the given message, then stop for review. Tick the box in the same commit.

**Done when:** one command brings up the infra; all three apps run; `/health/ready` reflects real dependency state (stop Redis and it reports unhealthy); CI is green.

## Steps

- [x] **0. Close M0.** Done in the owner's teach-back session (tag `m0-workflow`).
- [x] **Prep: checklist, permissions and the `.env` commit guard.**
  - Check: the hook blocks `git commit` with a staged `.env` from both the Bash and PowerShell tools, shown live.
  - Commit: `chore: add M1 checklist, permissions and .env commit guard`
- [x] **1. Workspace root.** Root `package.json` (pinned pnpm, Node engine), `pnpm-workspace.yaml`, strict `tsconfig.base.json`, ESLint flat config, Prettier, first `docs/STACK.md`.
  - Check: `pnpm install`, `pnpm lint`, `pnpm typecheck` and `pnpm format:check` pass.
  - Commit: `chore: set up pnpm workspace with strict TypeScript, ESLint and Prettier`
- [x] **2. ADRs.**
  - Write ADR-0005 (Kafka client), ADR-0006 (validation), ADR-0007 (Redis client) and ADR-0008 (health check design).
  - Change the planned-ADR references in ADR-0002 (rate limiting, fail-open/fail-closed) and ADR-0003 (outbox relay, partitioning) to name those ADRs by title, not number.
  - Add a note to Appendix B of the plan that its numbers are indicative (approved by the owner).
  - Check: owner review.
  - Commit: `docs: add ADRs for Kafka client, validation, Redis client and health checks`
- [ ] **3. Docker Compose.**
  - `infra/docker/docker-compose.yml`: Postgres, Redis, Kafka (KRaft, with a container listener and a host listener), Kafka UI and Mailpit, each with a healthcheck and a named volume.
  - `.env.example`; `pnpm infra:up`, `infra:down`, `infra:ps` and `infra:logs`.
  - Check: `pnpm infra:up`, then `pnpm infra:ps` shows all five services healthy. Kafka UI sees the broker. The Mailpit UI opens.
  - Commit: `chore: add docker compose for postgres, redis, kafka, kafka-ui and mailpit`
- [ ] **4. API bootstrap.**
  - `apps/api`: NestJS app, zod-validated config, `GET /health/live`.
  - Add the ESLint-on-edit hook and show it working. Remove it if it slows edits.
  - Check: a unit test shows a missing env var is rejected with a clear message. Supertest: `/health/live` returns 200. Booting without a `.env` exits non-zero.
  - Commit: `feat(api): bootstrap NestJS API with validated config and liveness endpoint`
- [ ] **5. Logging.** pino JSON logs, request ID, redaction.
  - Check: the response carries `X-Request-Id`, and a supplied ID is echoed back. A test shows `authorization` is redacted in log output.
  - Commit: `feat(api): add structured logging with request IDs and redaction`
- [ ] **6. Readiness.** `packages/infrastructure` probes for pg, Redis and Kafka, each with a timeout; `GET /health/ready` through terminus.
  - Check: unit tests with fake probes. All up returns 200. A critical probe down returns 503 and names it. Kafka down still returns 200 and reports Kafka as down.
  - Demo: `docker compose stop redis` gives 503; starting it again gives 200.
  - Commit: `feat(api): add readiness endpoint checking postgres, redis and kafka`
- [ ] **7. Worker.** `apps/worker`: standalone application context; connects, logs and shuts down cleanly.
  - Check: on dev start it logs "connected" for each dependency. Ctrl+C logs a clean shutdown. Stopping Kafka logs an error and a retry.
  - Commit: `feat(worker): bootstrap standalone worker that connects and logs`
- [ ] **8. Dashboard.** `apps/dashboard`: Next.js shell, Tailwind, zod env, a small fetch client, and a status page showing readiness. Strict CORS on the API.
  - Check: the dashboard build passes. The status page goes red when Redis is stopped.
  - Commit: `feat(dashboard): add Next.js shell with API client and status page`
- [ ] **9. Dev script and CI.** Root `pnpm dev` runs all three apps. GitHub Actions runs lint, typecheck, test and build.
  - Confirm the Linux Kafka binary installs in CI.
  - Record measured task times (Turborepo decision) in STACK.md.
  - Fill in "Commands" in CLAUDE.md.
  - Check: push, then the owner confirms CI is green in the browser.
  - Commit: `ci: add lint, typecheck, test and build workflow`
- [ ] **10. Verify the "Done when".** Run it end to end with real output; update the docs index.
  - Commit: `docs: verify M1 done-when and update docs index`
